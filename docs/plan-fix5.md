# 修正5「お祝いで跳ねると、体の編み目の模様がずれる」計画

## 症状(愛海のiPhoneで)
- 完成のお祝いで、パートナーが跳ねるときに、体の編み目の模様が体からずれる(ひつじ・ねこ)
- オコジョでは、模様がずれるだけでなく、白い線のようなものも入る

## 調べたこと

### 1. 部品がどのまとまりに入っているか(6匹とも)
WebKit で実際の画面の絵を調べた。**6匹とも、体・編み目の四角(stitch の pattern を塗った四角)・切り取りの型(clipPath)・身につけた作品は、すべて同じまとまり(`.pt-react` の中の `.pt-breath`)に入っている**。
- ひつじ・ねこ・オコジョ・ラッコ:clipPath と、それで切り取る四角は `pt-react > pt-breath`
- ウーパールーパー・アザラシ:上と同じ。セーターの mask・clipPath も `pt-react > pt-breath > pt-wear`
- 影だけが外(動かない。これは決めたとおり)
- 手袋は手のまとまりの中(手と一緒に動く。これも決めたとおり)

お祝い(`.pt-react`)・ふれあい(`.pt-react`)・呼吸(`.pt-breath`)は、体も模様も型も同じまとまりごと動かしている。**「模様と型が跳ねるまとまりの外にある」という見立ては、今の作りには当てはまらない。**
編む・ほどくは手のまとまり(`.pt-hand-l` / `.pt-hand-r`)だけが回る。体・模様・型は動かない(決めたとおり)。

### 2. WebKit(Playwright の webkit。WebKit 18.2)で写した結果
お祝いの前・最中・後を、6匹すべて写した。
- 本物の流れ(編む画面 → メモ → この作品を完成にする)でお祝いを出して写した画像(前・最中7コマ・後)
- パートナーの画面でお祝いの目印を付けて写した画像
- 動いている最中にその場で止めた絵と、同じ時刻の姿を新しく描き直した絵を、1画素ずつ比べた(6匹 × お祝い・ふれあいの跳ねる・ふれあいのゆれる・編む・ほどく × 3つの時刻 = 90通り)→ **90通りすべて、ちがう画素は0**
- お祝いを動画にも撮った(画面に実際に描かれたとおり)。動画は粗く、細かい編み目は見分けられなかった

**→ Playwright の WebKit では、ずれも白い線も出なかった。**
Playwright の WebKit は Windows で動く版で、iPhone の Safari と同じ WebKit でも、画面の描き方がちがう。iPhone は画面を小さな区画に分けて、変わったところだけを描き直し、GPU で重ねる。写真を撮るときは、毎回ぜんぶを描き直す。そのため、「動いている最中に、描き直しが一部だけ遅れる・抜ける」たぐいの不具合は、写真には写らない。

### 3. 原因(見立て)
はっきり確かめられたのは、ここまで:
- 今の作りでは、跳ねる・ゆれる・呼吸の動きを、**SVGの中のまとまり(`<g>`)に CSS で付けている**。動くたびに、iPhone は SVG の中身を描き直す
- 体の編み目は「四角を clipPath で体の形に切り取る」作り。身につける作品(セーター)も mask・clipPath を使っている
- iPhone の Safari は、CSS で動いている SVG のまとまりの中で clipPath・mask を使った部分を描き直すとき、切り取りの型の位置の計算や、描き直す範囲がずれることがある(WebKit で知られている、描き直しのたぐいの不具合)
  - 模様が体からずれる:体は新しい位置に描かれ、切り取った模様だけ前の位置のまま残る
  - オコジョの白い線:描き直しが抜けた細い範囲に、前のコマの絵や背景が見えている
- どちらも、ひつじ・ねこ・オコジョで同じ作り(clipPath で切り取った編み目)なので、同じ原因と考える

Windows の WebKit で出ないので、**これが本当の原因かは、iPhone で直したあとの絵を見るまで確かめられない**(→ 確認したいこと 1)。

## 直し方(案)

### 案A(おすすめ):体ごと動かす動き(呼吸・ふれあい・お祝い)を、SVGの外で動かす
SVGの中の `<g>` を動かすのをやめ、**SVG の絵そのもの(HTMLの部品)を動かす**。
- iPhone は、HTMLの部品に付けた CSS の transform の動きを、描き上がった1枚の絵として GPU で動かす。動いている間は SVG の中身(clipPath・mask・模様)を描き直さないので、型がずれたり、描き直しが抜けたりしない
- 影は動かさないので、影だけ別の SVG にして下に重ねる

絵の作り(下から):
```
<div class="partner">
  <svg class="pt-shadow">影</svg>                         … 動かない
  <div class="pt-react">                                   … ふれあい・お祝い(跳ねる・ゆれる)
    <svg class="pt-svg pt-breath">体・身につけた作品・編み地・左右の手・頭飾り</svg>  … 呼吸
  </div>
</div>
```
- 手(編む・ほどく・お祝いで手をふる)・まばたき・頭飾りの揺れは、今までどおり SVG の中のまとまりで動かす(その中には clipPath や mask の付いた部品はなく、体が動いていないので型はずれない)
- 新しい絵(PNG)の子も同じ作り

**動きの見た目は変えない**:
- 今の値は「絵の座標」(240×240 の中での長さ)。たとえば跳ねる高さ 22 は、絵の大きさの 22/240。HTMLの部品を動かすときも、同じ割合になるように直す
  - `.partner` を「大きさの入れ物」(`container-type: inline-size`)にして、絵の座標の1 = `100cqw / 240` で計算する(iPhone の Safari 16 から使える)
  - 跳ねる高さ(`--celebrate-hop` 22・`--react-hop` 16)・呼吸の高さ(`--breath-distance` 2.5)は、tokens.css の数字はそのまま、単位を「px」から「絵の座標」に変える(書き方:`--celebrate-hop: 22; /* 跳ねる高さ(絵の座標。240の中で) */`)。速さ・角度・回数は今のまま
  - 回転の中心(120, 214)は、`50% 89.1667%`(214/240)にする
- 動きのきっかけ(`data-celebrate` `data-react` `data-live`)・速さ・時間・くり返しの回数・「視差効果を減らす」のときの止め方は変えない
- 動きの名前(`pt-react` `pt-breath`)も変えないので、ほかの画面のCSSはそのまま

### 案B(小さな直し):切り取りの型(clipPath・mask)を、動くまとまりの外(いちばん上の defs)に出す
- SVGの決まりでは、型をどこに置いても、切り取られる部品の位置で使われるので、見た目は変わらない
- 動いているまとまりの中に型があると、WebKit は動くたびに型を作り直す。外に出すと作り直しが減る
- ただし、描き直しのずれそのものが、なくなるとは言い切れない

→ **案Aで直す**(案Bも一緒に入れてよい。害はない)。案Aは絵の作りを変えるが、素材(assets/)は変えない。並び・目印の付け方を変えるだけ
