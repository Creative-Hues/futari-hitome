# 修正3「新しい絵(画像AIのイラスト)を使える仕組み」計画

## Context
修正2は iPhone で確認ずみ。創が画像AIで描いた絵(透明PNG)を、今のSVGの絵と差し替えられるようにする。
本物の絵はまだない(ひつじ1匹分を作っているところ)。そこで、**今のSVGから書き出した仮のPNG**で仕組みを確かめる。
仮のPNGは確かめ用なので `assets/art/` には入れない。本物の絵が届いたら、`assets/art/` に入れるだけで使われるようにする。

## 今のアプリで確かめたこと
- 絵は、どうぶつのSVG(240×240)に、身につけた作品・編み地・左右の手・頭飾りを重ねた1枚のSVGにしている。動き(呼吸・まばたき・編む・ほどく・ふれあい・お祝い)は、その中のまとまり(`.pt-breath` `.pt-eye` `.pt-hand-l` など)に CSS の動きを付けている
- art-guide の下敷き画像(960×960)は、**今のSVGをちょうど4倍にした位置**になっている(足もとの線 856 = 214×4、頭飾りの位置 ひつじ(480, 200) = (120, 50)×4、手の回転の中心 (408, 600) = (102, 150)×4)
  - 頭飾り 272×272 の触れる点 (136, 247)、部屋に飾る作品 288×232 の触れる点 (144, 208) も、今のSVGの4倍
  - → PNGも「240×240 の中に4分の1の大きさで置く」と、今の動きの設定(回転の中心など)をそのまま使える。SVGとPNGを混ぜても位置が合う
- **ちがうところが1つ**:下敷き画像の「編み地(最大の高さ)」の四角は y=528〜704(上に伸びる形)。今のアプリの編み地は、上の端が y=584 で決まっていて、下に向かって 600〜760 まで伸びる(→ 確認したいこと 1)
- 体の色は、白い体のグラデーション3色・編み目の線・しっぽの線を、選んだ色から作った色に差し替えている(修正2)
- 目の色:ひつじ以外は「くろ(もとの色)」+4色、ひつじは「しろ(もとの色)」+きいろ・みずいろ・ピンク
- データ(保存の形)は変えなくてよい。絵の選び方は、今あるデータ(どうぶつ・体の色・目の色・頭飾り・身につけた作品・作品の編み方)だけで決まる → **データのバージョンは7のまま**

## 1. 絵の置き場所と、PNGがあるかどうかの決め方
- 本物の絵:`assets/art/` に art-guide のファイル名のまま入れる(`sheep_body.png` など)。中身は変えない
- アプリは、部品ごとに「PNGがあればPNG、なければ今のSVG」を選ぶ

| 部品 | PNG | ないとき |
| --- | --- | --- |
| どうぶつの体 | `<どうぶつ>_body.png` | その子は今のSVGの絵のまま(下の部品もすべてSVG) |
| 体の色を付ける場所 | `_body-mask.png` | 体の色を付けない(体の色を選んでいても絵のままの色) |
| 目 | `_eyes.png` | 今のSVGの目 |
| 手(棒針) | `_hand-left_knit.png` / `_hand-right_knit.png` | 今のSVGの手と編み針 |
| 手(かぎ針) | `_hand-left_crochet.png` / `_hand-right_crochet.png` | 棒針の手(PNGがあればPNG、なければSVG) |
| 頭飾り | `deco_<名前>.png` | 今のSVG |
| 身につける作品 | `wear_<部門>_<どうぶつ>.png`(手袋は `_left` / `_right`) | 今のSVG |
| 部屋に飾る作品 | `room_<名前>.png` | 今のSVG |

- 体のPNGがある子だけが「PNGの絵」になる。体がSVGの子に、PNGの手や目だけを付けることはしない(形が合わないため)
- 体がPNGの子では、ない部品だけSVGで出す(位置は4倍の関係で合う。絵柄はちがって見える)
- 手の左右は2枚そろったときだけPNG(片方だけのときは両方SVG)。手袋の左右も同じ
- 背景(原っぱ・部屋)は、art-guide で「あとでよい」なので修正3では入れない(→ 確認したいこと 8)

## 2. 位置のずれを直す `assets/art/art.json`
- 数字はすべて、art-guide と同じ **960×960 のキャンバスの点(px)**で書く。アプリが4で割って使う
- 書いていない項目は、art-guide のとおり(=今のSVGの4倍)の値を使う。数字でないもの・大きすぎるものは使わず、決まりの値にする(壊れていてもアプリは止まらない)
- 例:

```json
{
  "animals": {
    "sheep": {
      "decoration": { "x": 480, "y": 200 },
      "hatDecorationY": 140,
      "handLeft": { "x": 408, "y": 600 },
      "handRight": { "x": 552, "y": 600 },
      "knit": { "x": 416, "y": 584, "width": 128, "minHeight": 16, "maxHeight": 176 }
    }
  },
  "decorations": { "tulip": { "x": 136, "y": 247 } },
  "room": { "cushion": { "x": 144, "y": 208 } }
}
```

- 項目:頭飾りの位置/帽子のときの頭飾りの高さ/左右の手の回転の中心/編み地の場所(左上・幅・いちばん短いとき・いちばん長いときの高さ)/頭飾りの触れる点/部屋に飾る作品の床に触れる点
- 手の回転の中心は、今は CSS に書いてある数字(102px 150px)。PNGの子だけ、art.json の数字をその子の絵に渡して使う(動きの速さ・角度は今までどおり tokens.css)
- 最初の art.json は、ひつじの分だけ「art-guide のとおりの値」を書いた形で入れる(あとから数字を変えるだけで直せるように)。書き方は `assets/art/README.md` に書く

## 3. 重ね方と動き(PNGの子)
- 重ねる順は今と同じ(下から):**影 → 体(+目)→ 身につけた作品 → 編み地 → 左右の手(手袋も手の中)→ 頭飾り**
  - 影は今のSVGと同じ楕円をアプリが描く(呼吸で動かない)(→ 確認したいこと 3)
  - 目は体のすぐ上(体の一部として扱う)
- 1つのSVG(240×240)の中に、PNGを `<image>` で置く。今のまとまりの名前(`.pt-breath` `.pt-react` `.pt-eye` `.pt-hand-l` `.pt-hand-r` `.pt-knit` `.pt-deco` `.pt-wear`)をそのまま使うので、**動きの CSS と tokens.css は今のまま**で、PNGでも同じように動く
  - 呼吸・ふれあい・お祝い:体ごと動く(今と同じ)
  - 編む・ほどく・お祝いの手:手の画像を art.json の回転の中心で回す
  - まばたき:目の画像を縦につぶす。目の画像は、目のある場所だけに切り出して置く(つぶす中心が目の高さになるように。下の 5)
  - 頭飾りの揺れ:頭飾りの画像の下の真ん中を中心に揺らす(今と同じ)
- 編み地はアプリが描く(今の編み目模様の四角。色は作品の色)。場所は art.json の `knit`、高さは進み具合で `minHeight`〜`maxHeight`
- かぎ針の作品では、かぎ針用の手を使う。どの絵の手にするかは、そのとき出している作品の編み方で決める
  - 編む画面・ホームの作品カード・お祝い・完成記録・アルバム:その作品の編み方
  - パートナーの画面・なかま・新しく編むの選択肢:その子が今編んでいる作品の編み方。なければ棒針
- 帽子をかぶっているときの頭飾りの高さ、ひつじの帽子で頭飾りが絵の上にはみ出すときに縮める仕組みも、art.json の数字で今と同じように動かす

## 4. 色の付け方
色を付けた画像は、**表示する前に1回だけ作り**(canvas で画素ごとに計算)、できた画像を使う。数えるたびや動きのたびには作り直さない。同じ絵・同じ色の組み合わせは、アプリを開いている間は使い回す。
- 呼吸などの動きのたびに色の計算(ブレンドやフィルター)を iPhone にさせないため。CSS の `mix-blend-mode` や SVG のフィルターは、動いている絵では重くなりやすいので使わない
- **体**:`body-mask.png` の白い場所にだけ、体の色を掛け合わせる(白は全部、灰色はその割合だけ、黒・透明は付けない)。「もとの色」のときは何もしない
  - 色の濃さを調整できるように、`src/config/room.ts` の `BODY_TONE` に「掛け合わせる前に白を混ぜる割合」(最初は0)を足す。仮のPNGで、SVGの体の色と並べた比べる画像を作って値を決める
- **目**:目の色を付ける(→ 確認したいこと 2。「掛け合わせ」だとひつじの白い目が灰色になるため、形だけ使って選んだ色で塗る案)
- **身につける作品・部屋に飾る作品**:作品の色を掛け合わせる(白いところは作品の色、灰色の影はその分暗く、濃い輪郭線は濃いまま)
- **頭飾り**:色を変えない(絵のまま)

## 5. 絵を軽くする(縮小した版)
- 案:**`npm run art` という小さな変換の道具を作り、`assets/art/` の元の絵から、アプリで使う軽い版を作る**(元の絵は変えない)
  1. まわりの透明な部分を切り落とす(切った位置は一緒に書き出す表に残し、アプリが元の位置に置き直す)。目の画像はこれで「目のある場所だけ」になる
  2. 色の数を減らしたPNG(256色)にする。AIの絵は細かい色が多いので、ふつう元の3〜4割の重さになる
  3. 大きさは縮めない。いちばん大きく出す編む画面でも幅約300px(iPhoneでは約900画素)なので、960のままにする。重すぎるときは縮める割合を1か所で変えられるようにする
  4. `body-mask` は白黒だけの小さなPNGにする
- 作った軽い版は `src/art/generated/` に置き、git には入れない(元の絵から毎回作る)。`npm run dev`・`npm run build`・`npm test` の前に自動で動くようにする(Cloudflare Pages でもビルドの前に作られる)
- 変換の道具は JavaScript だけで動く小さな部品を使う(開発用の部品として `package.json` に足す。アプリの中には入らない。外部のサービスは使わない)。候補:`upng-js`(PNGの読み書きと色数を減らす)
- アプリはオフラインで動くように、作った絵をすべて最初に保存する(今の設定 `globPatterns` に png が入っているので、そのまま入る)
- 変換のたびに、元の重さ → 軽い版の重さの一覧を表示する。修正3の終わりに、仮の絵で合計の重さを伝える

## 6. 仮のPNG(確かめ用。assets/art/ には入れない)
- 今のSVGから、art-guide のファイル名・大きさ(4倍)のとおりにPNGを書き出す小さなスクリプトを作る。スクリプトと書き出したPNGは scratchpad(作業用の一時フォルダ)に置き、プロジェクトには入れない
  - 体:目・手・編み地・影をのぞいた体を、体の色を付けない白のまま
  - body-mask:体の白い毛(体の色を付ける場所)を白、ほかを黒
  - 目:目だけ(確認したいこと 2 の答えに合わせた色)
  - 手(棒針):今の手と編み針
  - 手(かぎ針):今のSVGにかぎ針の絵はないので、確かめ用に「左手=編み針を消した手」「右手=編み針の色だけ変えた手」にする(新しく描かない。見分けるためだけ)
  - 身につける作品・部屋に飾る作品:白〜うすいグレーにした今の絵
  - 頭飾り:今の絵のまま
- アプリには「絵を読む場所」を切り替える設定(`npm run art` に場所を渡す)を付け、仮の絵の場所を渡して確かめる。ふだんは `assets/art/`
- 確かめるときの組み合わせ:
  - 6匹すべて仮のPNG
  - **ひつじだけ**仮のPNG(ほかの5匹はSVG)
  - ひつじの体はあるが、目・かぎ針の手・body-mask がない(部品ごとにSVGに戻るか)
  - 頭飾り・身につける作品・部屋に飾る作品の一部だけPNG

## 7. 確かめ方
- **テスト(npm test)**:art.json の読み方(書いていない・壊れている値は決まりの値)/部品ごとのPNGかSVGかの選び方/色の付け方の計算(小さな画素の並びで)/切り落とした位置の戻し方/PNGの子の絵の重なり順とまとまりの名前
- **ブラウザでの確かめ**(scratchpad のスクリプト。修正2と同じ道具):
  1. `assets/art/` が空のとき、全部の画面の絵が修正2と**1画素も変わらない**こと(今の絵の作りを変えていないことの確かめ)
  2. 仮のPNGのとき、SVGの絵と並べて重ねた画像を作り、位置のずれがないこと(体の色・目の色・帽子と頭飾り・手袋・かぎ針・部屋に飾る作品)
  3. 編む・ほどく・ふれあい・お祝い・まばたき・呼吸で、PNGのまとまりが動いていること(動いている途中の回転や位置を読む)
  4. 混ぜたとき(ひつじだけPNGなど)に、どの画面も絵が出ること
  5. 修正2で作ったはみ出しの自動チェック(30画面×3つの幅)も、もう一度通す
- 比べる画像の場所を伝える

## 8. そのほか
- 「素材は描き直さない」:アプリは新しい絵も中身を変えない(読み込んだあと、切り落とし・色数を減らす・色を掛ける・置く場所を決めるだけ)。仮の絵も今のSVGを書き出しただけで、形は変えない
- 今までの動き(拡大しない・すばやいタップ・音声・パートナーの動き・写真・完成と記録・身につける作品・部屋・書き出しと読み込み・お休み)は変えない。PNGの絵が読み込めないとき(ファイルがこわれている等)は、その子はSVGの絵で出す
- 絵の読み込みと色付けが終わるまでは、絵の場所を空けたまま待つ(SVGの絵がちらっと見えたりしないように)
- 終わったら SPEC.md の「絵と素材」「フェーズ分け」と、`assets/art/README.md`(置き方・art.json の書き方・`npm run art`)を書く
- テストとビルドが通ったら、修正2と同じように main に push してよいか(→ 確認したいこと 9)

## 確認したいこと

### art-guide について(ガイドのほうを直せるところ)
1. **編み地の四角の位置**:下敷き画像では y=528〜704(上に伸びる)、今のアプリでは上の端 y=584 から下に伸びて 600〜760(いちばん長いとき)。
   - 案:**アプリに合わせて、下敷き画像とガイドを「上の端 584、いちばん長いと 760 まで下に伸びる。x=416〜544」に直す**(編み針の下に編み地が垂れる形。今のSVGの見た目と同じ)。胸の前の 416〜544 × 584〜760 は空けておく
   - 下敷き画像のとおり(上に伸びる)にしたいときは、art.json の値をそうしておき、PNGの子だけ上に伸びる形にもできる
2. **目の色**:ガイドは「うすいグレー(#d0d0d0)で描き、アプリが目の色を掛け合わせる」。掛け合わせだと、
   - ひつじの「しろ」は白にならず、#d0d0d0 の灰色のまま(白は掛け合わせで作れない)
   - ほかの色も、選んだ色より2割ほど暗くなる
   - 案:**目の画像は「形」だけ使い、選んだ色でそのまま塗る**(今のSVGと同じ色になる)。ガイドは「目は何色で描いてもよい。光の点などは入れず、塗りつぶした正円で。2つの目は同じ高さに」に直す
   - 目に光の点などを入れたいときは、別のファイル(`_eyes-light.png`、色を変えない)を足す形にもできる
3. **影**:ガイドに、足もとの影(地面の楕円)を体に入れるかが書いていない。体に入れると、呼吸やジャンプで影も一緒に動いてしまう。
   - 案:**体の絵には影を入れない。影はアプリが今と同じ楕円で描く**。ガイドに足す
4. **body-mask の描き方**:次をガイドに足したい
   - 輪郭線は黒にする(白にすると輪郭線にも色が付く。今のSVGも輪郭線には色を付けていない)
   - 白と黒の境目のぼかし(灰色)はあってよい。灰色はその割合だけ色が付く
   - 白い場所は体の絵の内側だけにする(体の外にはみ出した白は使わない)
5. **手袋とかぎ針の手**:手袋の絵は「手のファイルと同じ位置」だが、棒針の手とかぎ針の手で、手の形や位置がちがうと、1枚の手袋が合わない。
   - 案:**棒針とかぎ針で、手(手のひら)の形と位置は同じにし、ちがうのは道具だけ**にする。ガイドに足す
   - 手の形がちがう場合は、手袋も `wear_paws_cat_left_crochet.png` のように分ける形にもできる
6. **頭飾りのPNGの使い道**:頭飾りは、部屋の窓辺の鉢植えの花と、頭飾り・花を選ぶ画面の小さな絵にも使っている。
   - 案:**PNGがあれば、鉢植えと選ぶ画面の小さな絵にもPNGを使う**(絵柄がそろうため)
7. **art.json の数字の単位**:ガイドと同じ 960×960 のキャンバスの点(px)で書く案。頭飾り・部屋に飾る作品は、それぞれのキャンバス(272×272・288×232)の点で書く。これでよいか

### アプリについて
8. 背景(原っぱ・部屋)のPNGは、修正3では入れない(ガイドで「あとでよい」のため)。これでよいか
9. 絵を軽くする方法(5 の案:`npm run art` で透明な部分を切り落とし、256色のPNGにする。大きさは縮めない。開発用の部品 `upng-js` を足す)でよいか
