# フェーズ5「仕上げ」計画

## Context
フェーズ4は iPhone で確認ずみ(データの引き継ぎ・なかま・パートナーの画面・身につける作品・部屋の模様替え・音声の言葉、フェーズ1〜3の動き)。
今は、データは端末の IndexedDB の中だけにあり、ホーム画面のアプリを消すとすべて消える。設定画面には「部屋の模様替え」と「音声で数える言葉」の2つだけ。

フェーズ5の範囲(SPEC.md より)
- データの書き出し・読み込み、遊び方のヘルプ
- アイコンはフェーズ1の修正1で差し替え済みなので、今回は入れない

入れないもの:通知・書き出しのすすめを画面に出すこと(「最後に書き出した日」を設定に出すだけ)、端末間の自動同期、新しいアイコン。

## 今の状態で確かめたこと
- 保存している入れ物は5つ:`works`(作品。取り消しの履歴も中に持つ)・`partners`(6匹)・`photos`(写真。画像は Blob)・`room`(1件)・`settings`(1件。データのバージョン・+N の数・音声の言葉)。SPEC のデータ構造の5種類と同じ
- データのバージョンは今 4。古いデータを直す仕組み(`migrate.ts` の STEPS:1→2→3→4)は、IndexedDB の `get / getAll / put` だけを使って書かれている
- **並び替えはすでにすべてドラッグ**:ホームの編みかけの作品(タブも同じ並び)・編み図の写真・完成写真・+N の登録した数・部屋に飾る作品の5か所。どれも `useDragSort`(長押し0.35秒で持ち上げる)。↑↓のボタンで動かす場所は残っていない。アルバム(完成した日の順)・なかま(6匹の決まった順)・音声の言葉(順番に意味がない)は並び替えるものではない
- フェーズ5で増える一覧(ヘルプ)も並び替えるものではないので、新しくドラッグを付ける場所はない

## 1. データの書き出し

### ファイルの中身(1つの JSON)
```json
{
  "app": "futari-hitome",
  "fileVersion": 1,
  "dataVersion": 5,
  "exportedAt": "2026-10-11T09:30:00.000Z",
  "settings": { … },
  "works":    [ … ],
  "partners": [ … ],
  "room":     { … },
  "photos":   [ { "id": …, "workId": …, "kind": …, "order": …, "width": …, "height": …, "createdAt": …,
                  "blob": "data:image/jpeg;base64,…", "thumb": "data:image/jpeg;base64,…" } ]
}
```
- 5つの入れ物の中身を、**そのまま全部**入れる(作品の取り消しの履歴・編んだ時間・身につけている作品・飾っている作品も)
- 写真は縮小ずみの画像と一覧用の小さい版の両方を、文字(base64)に変換して入れる。元の写真は保存していないので、今の端末にある大きさのまま
- `app` は「ふたりひとめのファイルか」の目印、`fileVersion` はファイルの形の番号、`dataVersion` は中のデータの番号(今の形を直すしくみと同じ番号)
- 写真が多いとファイルが大きくなる(写真1枚あたり 0.3〜0.6MB ほど)。iPhone で重くならないよう、1枚ずつ文字にして、最後に1つのファイルにつなげる(大きな文字列を何度も作り直さない)

### ファイル名
- `futari-hitome-2026-10-11.json`(端末の時計の日付。同じ日に何度書き出しても同じ名前)

### 保存のしかた(iPhone は共有シート)
- 設定画面の「書き出す」を押す → ファイルを作る(写真が多いと少しかかるので「ファイルを作っています…」と出す)→ できたら **「保存する」ボタン**に変わる → 押すと共有シートが開き、「"ファイル"に保存」などを選べる
  - 2回押す形にするのは、iPhone の Safari では「ボタンを押した直後」でないと共有シートを開けないため(ファイルを作るのに時間がかかると、1回押しでは開けないことがある)
- 共有シートが使えないとき(`navigator.canShare({ files })` が使えない・false のとき)は、同じ「保存する」ボタンでふつうのダウンロードにする(PC のブラウザなど)
- 共有シートを閉じた(キャンセルした)ときは何もしない。「最後に書き出した日」も変えない
- 保存できた(共有シートで何かを選んだ/ダウンロードを始めた)ときに「最後に書き出した日」を今日にする
- うまくいかなかったときは「書き出せませんでした(理由)」と小さく出す。データは何も変わらない

### 最後に書き出した日
- 設定の書き出しの欄に「最後に書き出した日:2026年10月11日」、まだなら「まだ書き出していません」と出すだけ。通知・バッジ・催促の表示は出さない
- 保存場所は `settings` に `lastExportedAt` を足す(データのバージョン 4 → 5。下の 4)
- **この端末で書き出した日**を表す。読み込んだときは、ファイルの中の値ではなく、この端末の値をそのまま残す

## 2. データの読み込み

### 流れ
1. 設定の「読み込む」→ ファイルを選ぶ(iPhone では「ファイル」アプリから)。`accept` で種類をしぼりすぎると iPhone で JSON が選べなくなることがあるので、ゆるくしておき、中身で判断する
2. ファイルを読んで、**今のデータには触らずに**、メモリの中で中身を確かめる・今の形に直す・写真を画像に戻すところまでやる
3. 問題がなければ確認のシートを出す:
   - 「このファイルの中身」:書き出した日・編みかけ○つ・完成○つ・写真○枚・会ったなかま○匹
   - 「今のデータはすべて、このファイルの中身に置き換わります。元には戻せません。今のデータを残したいときは、先に書き出してください」
   - 「置き換える」(ピンク)/「やめる」
4. 「置き換える」で、5つの入れ物を**1回のまとまった保存(トランザクション)**で、全部消して入れ直す。途中で失敗したら IndexedDB が全部取り消すので、今のデータはそのまま残る
5. 終わったら「読み込みました」と出してホームへ。消されにくい設定(`requestPersist`)ももう一度頼む

### 読み込めないとき(今のデータは変えずに、理由を出す)
| ファイルの状態 | 出す文 |
| --- | --- |
| JSON として読めない(途中で切れている・ほかの種類のファイル) | 「このファイルは読み込めません。ふたりひとめで書き出したファイル(.json)を選んでください」 |
| `app` が違う・入れ物がそろっていない | 「ふたりひとめのデータではないようです」 |
| `fileVersion` / `dataVersion` が今のアプリより新しい | 「新しい版のアプリで書き出したファイルです。アプリを開き直して最新にしてから、もう一度読み込んでください」 |
| 中身が壊れている(作品に ID がない、数が数字でない、写真の画像が戻せない など) | 「ファイルの一部が壊れているため読み込めません(○○が読めません)」 |
| 保存の途中で失敗した | 「読み込めませんでした。今のデータはそのままです」 |
- 確かめる中身は「アプリが動くのに必要なところ」に絞る(作品の ID・名前・部門・パートナー・数、パートナーの動物、写真の ID・作品・画像 など)。知らない項目が増えていても、そのまま残す
- どの作品のものでもない写真(作品が見つからない写真)は、読み込まずに飛ばす

### 古いバージョンのファイル
- ファイルの `dataVersion` が今より古いときは、**今ある直し方(STEPS)をそのまま使って**今の形に直してから入れる
- そのために、ファイルの中身をメモリの中で「IndexedDB と同じ `get / getAll / put` が使える入れ物」に見せかける小さな仕組みを作り、STEPS をそこに対して動かす。STEPS の中身は変えない(端末のデータを直すときと、ファイルを直すときで、同じ直し方になる)
- 今のアプリで書き出したファイルはバージョン5だが、この先データの形を変えたとき(6, 7…)も、STEPS を足すだけで古いファイルが読める
- テストでは、バージョン1・3・4の形のデータで作ったファイルが今の形(5)になって読めることを確かめる

## 3. 遊び方のヘルプ(`#/settings/help`)
- 設定画面に「遊び方のヘルプ」のカード → ヘルプの画面。戻るで設定へ
- 見た目はほかの画面と同じ(白いカード・角丸・Zen Maru Gothic)。グループの見出しの下に、項目ごとに「名前+短い説明(1〜2文)」のカード
- **追記しやすくする**:中身は `src/data/help.ts` の1か所に、グループと項目の一覧(見出し・説明の文字だけ)として書く。画面はそれを並べるだけ。項目を足すときは help.ts に1行足せばよい
- 一番上に、SPEC の注意点どおり「データはこの端末の中だけにあります。ホーム画面のアプリを消すとデータも消えるので、ときどき設定の『書き出す』で保存しておくと安心です」の一文(ヘルプの中の説明。通知ではない)

### 入れる文(案)
**数える**
- 数え方:編む画面の下半分は、どこをタップしても1目数えます。1段の目数を入れた作品は、数え終わると段が自動で進みます。編んでいる間は画面が暗くなりません
- ＋N:まとめて数えます(10目編んだら「＋10」)。よく使う数を登録でき、長押しで動かして一番左にした数がボタンに出ます
- 取り消し:押し間違えたとき、直前の操作を1つずつ戻します
- ほどく:目や段をまとめて戻します。パートナーも一緒にほどきます
- 音声:「音声」をオンにして「あみ」と言うと1目、「10目」と言うとまとめて数えます。数える言葉は設定で変えられます。iPhone では止まることがあるので、そのときは指で数えてください
- 模様:数字の横の「＋ 2つ目」で、模様の回数などを数えます。「○段ごと」を入れると自動で進みます
- 目標なしの作品:バーの「今このくらい」をタップすると、パートナーがそこまで編み進めます

**作品**
- タブ:編みかけの作品が2つ以上あると、編む画面の上のタブで切り替えられます。並びはホームで長押しして変えられます
- 同じ子の切り替え:同じ子が2つの作品に入っているときは「こっちを編む」で、パートナーが編む作品を切り替えます
- メモと写真:「メモ」で毛糸・針・メモと、編み図の写真を残せます。写真は押すと大きく見られ、2本指で拡大できます
- 完成:目標に届くと「完成!」が出ます。メモの一番下からも完成にできます。写真と感想を残せます
- アルバム:完成した作品の記録です。パートナーごとに絞り込めます。「編みかけに戻す」もここから

**パートナー**
- なかま:6匹の一覧です。その子の部門の作品を編むと会えます。タップするとしぐさをします
- パートナーの画面:頭飾り・体の色・目の色・名前を変えられます
- 身につける:完成した作品はパートナーがもらって身につけます。パートナーの画面で付け替えられます。小物やインテリアは部屋に飾ります

**部屋と設定**
- 部屋の模様替え:歯車 → 部屋の模様替えで、壁や床の色・鉢植えの花・飾る作品(長押しで置き場所を入れ替え)を変えられます

**データ**
- 書き出しと読み込み:設定の「書き出す」で、写真も含めたすべてのデータを1つのファイルに保存します。iPhone では「"ファイル"に保存」を選んでください。「読み込む」でそのファイルから戻せます(今のデータは置き換わります)

(「目標なしの作品」とふれあい(なかまの中)は、挙げてもらった一覧に加えて入れました。いらなければ消します)
